Supabase Table Setup
Table: bookmarks
create table public.bookmarks (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  user_id uuid null,
  title text null,
  url text null,
  constraint bookmarks_pkey primary key (id)
);

Enable RLS & Policies
-- Enable Row Level Security
ALTER TABLE public.bookmarks ENABLE ROW LEVEL SECURITY;

-- Select only own bookmarks
CREATE POLICY "Select own bookmarks"
ON public.bookmarks
FOR SELECT
USING (user_id = auth.uid());

-- Insert only own bookmarks
CREATE POLICY "Insert own bookmarks"
ON public.bookmarks
FOR INSERT
WITH CHECK (user_id = auth.uid());

-- Delete only own bookmarks
CREATE POLICY "Delete own bookmarks"
ON public.bookmarks
FOR DELETE
USING (user_id = auth.uid());

Google OAuth Setup

Go to Google Cloud Console → Credentials

Create OAuth 2.0 Client ID → Web application

Set Authorized redirect URIs:

http://localhost:3000/ (development)

https://your-app.vercel.app/ (production)

Add your email as a Test User on the OAuth consent screen

Copy Client ID and Client Secret

In Supabase → Authentication → Providers → Google, enter the Client ID and Secret

Environment Variables

Create a .env.local file:

NEXT_PUBLIC_SUPABASE_URL=your-supabase-url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key

Supabase Client (lib/supabase.js)
import { createClient } from '@supabase/supabase-js';

export const supabase = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL,
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY
);

Troubleshooting

Deleted bookmarks reappearing:
Make sure RLS policies are set correctly. Delete queries must include user_id.

Google OAuth redirect_uri_mismatch:
Ensure the redirectTo in your login code exactly matches Google Cloud OAuth redirect URI.
